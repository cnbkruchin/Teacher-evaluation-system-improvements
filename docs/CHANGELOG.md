# ประวัติการเปลี่ยนแปลง

## v3.4.2

### แก้ปัญหา "ข้อมูลที่ป้อนลงในเซลล์ ... ละเมิดกฎการตรวจสอบข้อมูล"

**อาการ** เมื่อบันทึกผู้ประเมิน (หรือข้อมูลอื่นบางอย่าง) ระบบขึ้น Exception ว่า
*"ข้อมูลที่ป้อนลงในเซลล์ L3 ละเมิดกฎการตรวจสอบข้อมูลที่ตั้งไว้ในเซลล์นี้"* แล้วบันทึกไม่ได้

**สาเหตุ** ระบบรุ่นก่อนตั้งรายการเลือก (dropdown) ในชีทเป็นแบบ **"ปฏิเสธข้อมูลที่ไม่ถูกต้อง"**
กฎแบบนี้จะบล็อกทุกค่าที่อยู่นอกรายการ — รวมถึงค่าที่สคริปต์เป็นคนเขียนเอง
และกฎนั้น **ฝังอยู่ในไฟล์สเปรดชีตถาวร** แม้จะอัปเกรดโค้ดเป็นรุ่นใหม่แล้วก็ตาม

พอ v3.4 เปิดให้ผู้ดูแลเพิ่มบทบาทและขอบเขตได้เอง ค่าที่ระบบเขียนจึงหลุดออกนอกรายการเดิม
(เช่น ขอบเขตแบบ *กลุ่มสาระ/ฝ่าย* หรือรายชื่อครูที่เลือกเอง ซึ่งเดิมมีแค่ *ระดับชั้น* กับ *วันเวร*)
กฎเก่าที่ค้างอยู่จึงเริ่มขวางการบันทึก

**สิ่งที่แก้**

| จุดที่แก้ | ผลที่ได้ |
|---|---|
| รายการเลือกทุกจุดเปลี่ยนเป็นแบบ **เตือนแต่ไม่บล็อก** | ยังช่วยเลือกค่าได้เหมือนเดิม แต่ไม่ขวางการบันทึกอีก |
| **ติดตั้ง/อัปเกรดระบบ** ล้างกฎเก่าทั้งหมดก่อนตั้งใหม่ | กฎที่ค้างมาจากรุ่นก่อนถูกล้างทิ้งในครั้งเดียว |
| คอลัมน์ *ขอบเขต (ระดับชั้น/วัน)* ไม่ตั้งกฎอีกต่อไป | ค่าขึ้นกับประเภทบทบาท จึงต้องกรอกได้อิสระ |
| รายการเลือก *บทบาท* อัปเดตทันทีที่เพิ่ม/แก้/ลบบทบาท | ไม่เกิดกรณีบทบาทใหม่ไม่อยู่ในรายการของชีท |
| **ระบบกู้สถานการณ์ให้เองตอนบันทึก** | ถ้ายังเจอกฎแบบบล็อกค้างอยู่ ระบบจะล้างเฉพาะคอลัมน์นั้นแล้วบันทึกซ้ำให้ทันที ผู้ใช้ทำงานต่อได้โดยไม่ต้องรอผู้ดูแล |
| เพิ่มรายการตรวจใน **🩺 ตรวจสุขภาพระบบ** และการทดสอบตนเอง | เห็นล่วงหน้าว่ามีกฎแบบบล็อกค้างอยู่กี่คอลัมน์ พร้อมวิธีแก้ |

> **สำหรับไฟล์ที่ใช้งานอยู่แล้ว** เปิดเมนู **🏫 ระบบประเมินผล → ⚙️ ติดตั้ง / อัปเกรดระบบ** หนึ่งครั้ง
> เพื่อล้างกฎเก่าทิ้งทั้งหมด (ข้อมูลไม่หาย) หลังจากนั้นบันทึกได้ตามปกติ

### ชุดทดสอบจับข้อผิดพลาดประเภทนี้ได้แล้ว

เดิมตัวจำลอง Google Sheets ในชุดทดสอบไม่ได้บังคับใช้กฎการตรวจสอบข้อมูล บั๊กนี้จึงหลุดรอดไปได้
ตอนนี้ตัวจำลองโยน Exception เหมือนของจริงทุกประการ และเพิ่มการทดสอบชุดใหม่ 16 รายการ
ที่จำลองไฟล์ซึ่งอัปเกรดมาจากรุ่นก่อนพร้อมกฎเก่าที่ค้างอยู่ (รวมเป็น 366 รายการ)

## v3.4.1

### แก้ปัญหาทะเบียนครูกับตารางเวรเป็นข้อมูลคนละชุดกัน

ทะเบียนครูและตารางเวรรายภาคเรียนเก็บชื่อครูแยกกัน ทำให้ข้อมูลหลุดจากกันได้หลายทาง
เวอร์ชันนี้กำหนดบทบาทของข้อมูลให้ชัด แล้วปิดช่องที่ทำให้ข้อมูลเพี้ยนตั้งแต่ต้นทาง

**หลักการที่ระบบยึด**
- **ทะเบียนครู** เป็นแหล่งข้อมูลหลักของ *ชื่อ · ระดับชั้นที่ปรึกษา · สถานะ*
- **ตารางเวร** เป็นแหล่งข้อมูลหลักของ *เวรในภาคเรียนนั้น* (วัน · บทบาทในเวร · จุดปฏิบัติ · เวลา)
  ซึ่งยังคงแยกอิสระตามภาคเรียนได้ตามเจตนาเดิมของระบบ

**ปิดช่องที่ทำให้ข้อมูลหลุดจากกัน**
- **ลบครู** → ลบแถวเวรของครูคนนั้นทุกภาคเรียนไปด้วย (เดิมเหลือค้างเป็นข้อมูลผี)
- **ปิดใช้งานครู** → ปิดใช้งานแถวเวรของภาคเรียนปัจจุบันตามให้ทันที
- **นำเข้ารายชื่อครูจากไฟล์แล้วชื่อเปลี่ยน** → ชื่อในตารางเวรและผลการประเมินตามให้ด้วย
  (เดิมซิงก์เฉพาะตอนแก้ผ่านหน้าจอ ไม่ซิงก์ตอนนำเข้าไฟล์)
- **สร้างตารางเวรจากค่าเริ่มต้น** → ข้ามครูที่ปิดใช้งานแล้ว ไม่สร้างแถวเวรให้คนที่ไม่ได้ปฏิบัติงาน
- **เปลี่ยนเวรประจำวัน (ค่าเริ่มต้น)** → หน้าจอเตือนทันทีว่าตารางเวรของภาคเรียนปัจจุบันยังเป็นวันเดิม
  พร้อมตัวเลือก "อัปเดตตารางเวรของภาคเรียนปัจจุบันให้ตรงกันด้วย" (ติ๊กไว้ให้เป็นค่าเริ่มต้น)
  เพราะการเปลี่ยนวันเวรมีผลต่อสิทธิ์ของหัวหน้าเวรประจำวันทันที

**เครื่องมือตรวจและซ่อมความสอดคล้อง**
การ์ดใหม่ **"🔗 ความสอดคล้องกับทะเบียนครู"** ในหน้า *เวรประจำวัน* ตรวจให้ 7 เรื่อง

| รายการที่ตรวจ | ระดับ | ซ่อมอัตโนมัติ |
|---|---|---|
| แถวเวรของครูที่ไม่มีในทะเบียนแล้ว | ต้องแก้ | ลบแถวทิ้ง |
| แถวเวรซ้ำในภาคเรียนเดียวกัน | ต้องแก้ | ต้องแก้เอง |
| ชื่อในตารางเวรไม่ตรงกับทะเบียน | ต้องแก้ | แก้ชื่อให้ตรง |
| แถวเวรที่ยังไม่ได้ผูกรหัสครู | ต้องแก้ | ผูกรหัสให้ |
| ครูปิดใช้งานแล้วแต่แถวเวรยังใช้งานอยู่ | ควรตรวจ | ปิดใช้งานแถวเวร |
| ครูที่ยังไม่มีเวรในภาคเรียนนี้ | ควรตรวจ | สร้างเวรจากค่าเริ่มต้น |
| วันเวรต่างจากค่าเริ่มต้นในทะเบียน | แจ้งให้ทราบ | เปลี่ยนให้ตรง (ต้องติ๊กเอง) |

รายการที่ "ต้องแก้" ถูกติ๊กไว้ให้ล่วงหน้า ส่วนวันเวรที่ต่างกันจะ**ไม่ติ๊กให้**
เพราะหลายโรงเรียนตั้งใจให้เวรของแต่ละภาคเรียนต่างจากค่าเริ่มต้น

### แก้ไข
- **ระดับชั้นในรายงานไม่ตรงกับหน้าจออื่น** — เดิมรายงานใช้ "ระดับชั้นที่ดูแลในเวร"
  แต่หน้าอื่นและสิทธิ์ของหัวหน้าระดับชั้นใช้ "ระดับชั้นที่ปรึกษา" ในทะเบียนครู
  ตอนนี้ทุกที่ยึดทะเบียนครูเป็นหลักเหมือนกันแล้ว

### อื่น ๆ
- ชุดทดสอบอัตโนมัติเพิ่มจาก 318 เป็น **350 รายการ**

## v3.4.0

### บทบาทและขอบเขตของผู้ประเมิน — เพิ่มเองได้จากหน้าจอ
เดิมบทบาทผู้ประเมินถูกฝังไว้ในโค้ด 4 บทบาทตายตัว โรงเรียนที่มีโครงสร้างต่างออกไป
จึงเพิ่มผู้ประเมินกลุ่มใหม่ไม่ได้เลย เวอร์ชันนี้ย้ายบทบาทออกมาเป็นข้อมูลที่แก้ไขได้

- ชีทใหม่ **"บทบาทผู้ประเมิน"** และการ์ดจัดการบทบาทในหน้า **👥 ผู้ประเมิน**
- **เพิ่ม / แก้ไข / ปิดใช้ / ลบบทบาท** ได้เองจากหน้าจอ (สูงสุด 30 บทบาท)
- แต่ละบทบาทเลือก **ประเภทขอบเขต** ได้ 5 แบบ ว่าจะประเมินครูกลุ่มใด
  - **ทุกคน** — ครูทุกคนในโรงเรียน ไม่ต้องระบุขอบเขต
  - **ระดับชั้น** — ครูที่ปรึกษาของระดับชั้นที่รับผิดชอบ
  - **เวรประจำวัน** — ครูที่อยู่เวรวันเดียวกัน ตามตารางเวรของภาคเรียนนั้น
  - **กลุ่มสาระ/ฝ่าย** *(ใหม่)* — ครูในกลุ่มสาระหรือฝ่ายเดียวกัน
  - **เลือกครูเอง** *(ใหม่)* — ผู้ดูแลเลือกรายชื่อครูเป็นรายคน เหมาะกับคณะกรรมการเฉพาะกิจ
- **เพิ่มบทบาทใหม่ไปพร้อมกับการเพิ่มผู้ประเมินได้ในครั้งเดียว** — เลือก "➕ เพิ่มบทบาทใหม่..."
  ในช่องบทบาท แล้วกรอกชื่อและประเภทขอบเขตได้เลย ไม่ต้องออกไปสร้างบทบาทก่อน

### ขอบเขตที่เพิ่มเองได้
- ตัวเลือกขอบเขตรวมทั้ง **ค่ามาตรฐาน + ค่าที่มีอยู่จริงในทะเบียนครู + ค่าที่ผู้ดูแลเพิ่มเอง**
  จึงเห็นกลุ่มสาระและระดับชั้นที่โรงเรียนใช้จริงโดยไม่ต้องพิมพ์ซ้ำ
- ไม่มีตัวเลือกที่ต้องการ → กด **"➕ ระบุเอง"** แล้วพิมพ์ได้ทันที
  **ระบบจะจำค่าใหม่ไว้กับบทบาทนั้นให้เลือกจากรายการในครั้งถัดไปโดยอัตโนมัติ**
- บทบาทแบบ "เลือกครูเอง" มีช่องค้นหาและรายการติ๊กเลือกครู พร้อมตัวนับจำนวนที่เลือก

### ความปลอดภัยของข้อมูล
- **เปลี่ยนชื่อบทบาทแล้วระบบตามไปแก้ให้ทุกที่** ทั้งทะเบียนผู้ประเมิน กลุ่มผู้ประเมินของชุดประเมิน
  ผลการประเมิน และคลังข้อมูลย้อนหลัง — ข้อมูลจึงไม่ขาดการเชื่อมโยง
- **ปิดใช้งานบทบาทที่ยังมีผู้ประเมินอยู่ไม่ได้** และ **ลบบทบาทที่เคยมีผลการประเมินไม่ได้**
  (ให้เปลี่ยนสถานะเป็น "ไม่ใช้งาน" แทน เพื่อรักษาข้อมูลย้อนหลัง)
- ผู้ประเมินที่ใช้บทบาทซึ่งไม่มีอยู่แล้วจะถูกเตือนไว้ด้านบนของหน้า พร้อมป้าย "ไม่พบบทบาท"
- ใช้บทบาทที่เพิ่มเองเป็นสมาชิกของกลุ่มผู้ประเมินในชุดประเมินได้ตามปกติ

### การอัปเกรดจาก v3.3 (ไม่มีข้อมูลสูญหาย)
- ระบบสร้างชีท "บทบาทผู้ประเมิน" พร้อมบทบาทมาตรฐาน 4 บทบาทและประเภทขอบเขตเดิมให้อัตโนมัติ
- บทบาทที่พบในทะเบียนผู้ประเมินแต่ยังไม่มีในชีท (เช่น ที่พิมพ์เพิ่มเองในชีท)
  จะถูกเพิ่มให้เป็นแบบ "ทุกคน" พร้อมหมายเหตุให้ตรวจสอบประเภทขอบเขต
- สิทธิ์การเห็นครูของผู้ประเมินเดิมเหมือนเดิมทุกประการ

### อื่น ๆ
- หน้า "ผู้ประเมิน" แสดงขอบเขตแบบเลือกครูเองเป็นชื่อครู (เช่น "นายสมชาย ใจดี และอีก 3 คน")
- ชุดทดสอบอัตโนมัติเพิ่มจาก 312 เป็น **347 รายการ**

## v3.3.0

### ชุดประเมิน — แยกเกณฑ์และคะแนนออกเป็นชุด ๆ ได้อิสระ
- เมนูใหม่ **"🧩 ชุดประเมิน"** สร้างชุดของเกณฑ์การประเมินได้หลายชุด (สูงสุด 20 ชุด)
  แต่ละชุดมีของตัวเองครบ: เกณฑ์การประเมิน · มาตราคะแนนต่อข้อ · กลุ่มผู้ประเมิน · น้ำหนัก
- **มาตราคะแนนกำหนดเองได้รายชุด** (2–100 คะแนนต่อข้อ) ไม่จำเป็นต้องเป็น 1–5 เสมอ
  หน้าจอผู้ประเมินและการตัดระดับผลปรับตามมาตราของชุดโดยอัตโนมัติ
- **กำหนดผู้ประเมินได้อย่างอิสระ** เป็น "กลุ่ม" 2 แบบ
  - **แบบบทบาท** — ทุกคนที่มีบทบาทนั้นเป็นผู้ประเมินของกลุ่ม (รวมหลายบทบาทในกลุ่มเดียวได้)
  - **แบบรายบุคคล** — เลือกผู้ประเมินรายคน (มีสิทธิ์เหนือกว่าแบบบทบาท ใช้กำหนดทับเป็นรายกรณีได้)
- กำหนดน้ำหนัก % ของแต่ละกลุ่มแยกตามชุด และเปิด/ปิดการถ่วงน้ำหนักรายชุดได้
- **คัดลอกชุด** พร้อมเกณฑ์และกลุ่มผู้ประเมินทั้งหมด · **ปิดใช้งาน** ชุดที่ไม่ใช้แล้ว ·
  **ลบ** ได้เฉพาะชุดที่ยังไม่มีผลการประเมิน (ป้องกันข้อมูลหาย)
- ผู้ประเมินเลือกชุดที่ได้รับมอบหมายได้เองในหน้าแบบประเมิน และเห็นว่าตนอยู่กลุ่มใด
- เกณฑ์ของแต่ละชุดแยกกันสมบูรณ์ — ครูคนเดียวกันถูกประเมินหลายชุดในภาคเรียนเดียวกันได้โดยไม่ทับกัน

### แปลงเป็น "คะแนนที่หน่วยงานได้รับ"
- แต่ละชุดกำหนดได้ว่าคะแนนสุทธิจะถูกแปลงเป็นคะแนนเต็มเท่าไรของหน่วยงาน
  **คะแนนที่ได้รับ = คะแนนสุทธิ ÷ คะแนนเต็มต่อข้อ × คะแนนเต็มที่หน่วยงานกำหนด**
- ตัวอย่าง ชุดเต็มข้อละ 5 และหน่วยงานให้ 20 คะแนน → สุทธิ 5.00 ได้ 20.00 · สุทธิ 4.25 ได้ 17.00
- ถ้ามีหลายชุด ระบบรวมคะแนนที่ได้รับของทุกชุดเป็นคะแนนรวมต่อครู 1 คน
- แสดงผลครบทั้งแดชบอร์ด หน้าประมวลผล ชีท "สรุปผลการประเมิน" และไฟล์ที่ส่งออก
- ใส่ 0 = ไม่แปลงคะแนน ระบบจะแสดงคะแนนสุทธิตามมาตราของชุดตามเดิม

### รายงานรูปแบบใหม่
- แผ่นงาน **"คะแนนรายชุดประเมิน"** — ตารางครู × ชุดประเมิน แสดงคะแนนที่ได้รับของแต่ละชุด
  คะแนนรวม ร้อยละ ระดับผล และแถวค่าเฉลี่ยของทั้งกลุ่ม (ใช้กรอกแบบประเมินของโรงเรียนได้ทันที)
- **รายงานรายบุคคล** ปุ่มใหม่ในหน้าประมวลผล/ส่งออก — **1 คน 1 หน้ากระดาษ**
  ประกอบด้วยข้อมูลครู ผลแยกตามชุดประเมิน คะแนนเฉลี่ยรายข้อ ข้อเสนอแนะจากผู้ประเมิน และช่องลงนาม
  (ครั้งละไม่เกิน 80 คน เพื่อไม่ให้ชนขีดจำกัดเวลาทำงานของ Apps Script)
- รายงานสรุปเดิมเพิ่มคอลัมน์ "คะแนนที่หน่วยงานได้รับ" และหมายเหตุอธิบายที่มาของคะแนนเต็มแต่ละชุด

### ติดตามและควบคุมคุณภาพรอบการประเมิน
- เมนูใหม่ **"📈 ติดตามความคืบหน้า"**
  - เห็นทันทีว่าผู้ประเมินคนใดค้างชุดใด เหลือกี่คน คิดเป็นกี่ %
  - เห็นว่าครูคนใดยังขาดการประเมินจากกลุ่มใดของชุดใด
  - **ส่งอีเมลแจ้งเตือน**เฉพาะผู้ประเมินที่ยังทำไม่ครบ พร้อมรายการที่ค้าง กำหนดส่ง และลิงก์เข้าระบบ
    (เลือกผู้รับได้ · แนบข้อความเพิ่มเติมได้ · ครั้งละไม่เกิน 50 คน)
- เมนูใหม่ **"🔎 ตรวจคุณภาพการประเมิน"** — ตรวจก่อนสรุปผลว่ามีสัญญาณผิดปกติหรือไม่
  - ให้คะแนนเท่ากันทุกข้อ (straight-lining)
  - ผู้ประเมินที่ให้คะแนนสูง/ต่ำกว่าค่าเฉลี่ยของระบบอย่างชัดเจน
  - ผู้ประเมินที่ให้คะแนนครูทุกคนแทบไม่ต่างกัน (การกระจายใกล้ 0)
  - สัดส่วนการเขียนข้อเสนอแนะ และครูที่ยังขาดการประเมินจากกลุ่มที่มีน้ำหนัก
- **รอบการประเมิน** — เปิด/ปิดการบันทึกผล กำหนดช่วงวันที่เปิด-ปิด
  และ **ล็อกภาคเรียนที่สรุปผลแล้ว** เพื่อไม่ให้มีการแก้ไขย้อนหลัง
  (ตรวจสอบฝั่งเซิร์ฟเวอร์เสมอ ไม่ใช่แค่ซ่อนปุ่มบนหน้าจอ)

### โครงสร้างข้อมูล
- ชีทใหม่ **"ชุดประเมิน"** และ **"กลุ่มผู้ประเมินของชุด"**
- ชีท "เกณฑ์การประเมิน" เพิ่มคอลัมน์ `รหัสชุด`
- ชีท "ผลการประเมิน" และ "คลังผลการประเมิน" เพิ่มคอลัมน์
  `รหัสชุด` `ชุดประเมิน` `กลุ่มผู้ประเมิน` `คะแนนเต็มต่อข้อ`
- ชีท "สรุปผลการประเมิน" เพิ่มคอลัมน์ `คะแนนที่หน่วยงานได้รับ` และ `คะแนนเต็มที่หน่วยงานกำหนด`

เมื่อกดเมนู **ติดตั้ง / อัปเกรดระบบ** ระบบจะทำให้อัตโนมัติ

- ยกน้ำหนักกลุ่มผู้ประเมินจากการตั้งค่าเดิมมาใส่ให้ครบ ผลการคำนวณจึงเท่าเดิมทุกประการ

- หน้าเกณฑ์การประเมินและหน้าน้ำหนักผู้ประเมินมีตัวเลือกชุดประเมินอยู่ด้านบน

### คะแนนสุทธิแบบถ่วงน้ำหนักตามกลุ่มผู้ประเมิน
- เมนูใหม่ **"⚖️ น้ำหนักผู้ประเมิน"** กำหนดได้ว่าคะแนนจากผู้ประเมินแต่ละกลุ่ม
  (รอง ผอ. / หัวหน้ากลุ่มกิจการนักเรียน / หัวหน้าระดับชั้น / หัวหน้าเวรประจำวัน)
  จะคิดเป็นกี่ % ของคะแนนรวม
- สูตร: **คะแนนสุทธิ = Σ (คะแนนเฉลี่ยของกลุ่ม × น้ำหนักของกลุ่ม) ÷ Σ น้ำหนักที่ใช้จริง**
- ตัวเลือก **ปรับสัดส่วนอัตโนมัติ** เมื่อครูไม่ได้รับการประเมินจากบางกลุ่ม
  เพื่อไม่ให้เสียเปรียบ (เปิดไว้เป็นค่าเริ่มต้น)
- **ดูผลกระทบก่อนบันทึกได้** — เทียบคะแนนและอันดับก่อน-หลัง พร้อมลูกศรบอกอันดับที่เปลี่ยน
- แถบสัดส่วนและสูตรแสดงสดขณะปรับน้ำหนัก
- คะแนนสุทธิถูกใช้ในแดชบอร์ด การจัดอันดับ การเรียงลำดับก่อนส่งออก และรายงาน
- รายงานที่ส่งออกเพิ่มคอลัมน์ "คะแนนสุทธิ" และแผ่นงาน **"วิธีคิดคะแนนสุทธิ"**
  ที่แสดงน้ำหนักและตัวอย่างการคำนวณ เพื่อให้ตรวจสอบที่มาของคะแนนได้
- ค่าเฉลี่ยรวมแบบเดิมยังถูกเก็บและแสดงคู่กันเสมอ

  ค้นหาและกู้คืนได้ พร้อมหน้าดูพัฒนาการของครูรายคนข้ามภาคเรียน
- **ระบบกู้คืนรหัสผ่านผู้ดูแลระบบ 3 ช่องทาง** — OTP ทางอีเมล, เมนูสำหรับเจ้าของไฟล์,
  ฟังก์ชันฉุกเฉินจากตัวแก้ไขสคริปต์
- **จัดการเกณฑ์การประเมินจากหน้าจอ** เพิ่ม/แก้ไข/ปิดใช้/ตั้งน้ำหนัก รองรับสูงสุด 20 ข้อ
- จัดการทะเบียนครูจากหน้าจอ พร้อมนำเข้ารายชื่อจาก Excel
- ส่งรหัสผ่านให้ผู้ประเมินทางอีเมลอัตโนมัติ
- แดชบอร์ดแสดงความคืบหน้าการประเมินรายบุคคล
- หน้าประวัติการใช้งาน (audit log) และเมนูตรวจสุขภาพระบบ
- ชุดทดสอบอัตโนมัติ 125 รายการ (`tests/run-all.sh`) และฟังก์ชัน `runSelfTest()` ในระบบ

### ความปลอดภัย
- เปลี่ยนการเก็บรหัสผ่านจาก SHA-256 รอบเดียว + salt ร่วม
  เป็น **salt เฉพาะราย + วนแฮช 4,096 รอบ** (อัปเกรดรหัสผ่านเดิมอัตโนมัติ)
- เปรียบเทียบค่าแฮชแบบ constant-time
- ล็อกบัญชีเมื่อกรอกรหัสผ่านผิดเกินกำหนด ทั้งรายบัญชี รายเครื่อง และเพดานรวมทั้งระบบ
- เซสชันมี token, หมดอายุตามเวลาไม่ใช้งานและอายุสูงสุด, เพิกถอนได้เมื่อเปลี่ยนรหัสผ่าน
- ตรวจสอบสิทธิ์ฝั่งเซิร์ฟเวอร์ทุกครั้ง ไม่เชื่อข้อมูลจากหน้าเว็บ
- นโยบายรหัสผ่านขั้นต่ำ และบังคับเปลี่ยนรหัสผ่านครั้งแรก
- escape ข้อมูลผู้ใช้ทุกจุดก่อนแสดงผล (กัน XSS)
- ซ่อนและป้องกันชีทที่มีข้อมูลอ่อนไหว จำกัดบัญชี Google ที่เข้าระบบผู้ดูแลได้
- ใช้ LockService ป้องกันข้อมูลชนกันเมื่อมีผู้ใช้พร้อมกัน

### แก้ไขข้อบกพร่องของระบบเดิม
- **คะแนนเก็บเป็นสูตรในชีท** ทำให้ค่าพังเมื่อย้าย/ลบแถว → เปลี่ยนเป็นคำนวณและเก็บค่าคงที่
- **ประเมินซ้ำได้ไม่จำกัด** ทำให้สรุปผลคลาดเคลื่อน → หนึ่งผู้ประเมินต่อครูต่อภาคเรียนมีผลเดียว
  การบันทึกทับจะเก็บฉบับเดิมไว้ในคลัง
- **การลบผลการประเมินหายถาวร** → ย้ายเข้าคลังข้อมูลแทน
- **อ้างอิงข้อมูลด้วยชื่อ-นามสกุล** ทำให้ข้อมูลขาดเมื่อแก้ชื่อ → เพิ่มรหัสอ้างอิงถาวรและ
  ปรับชื่อให้ตรงกันทั้งระบบเมื่อมีการแก้ไข
- **`showPage()` พึ่งพาตัวแปร `event` ส่วนกลาง** → เขียนระบบเมนูใหม่ทั้งหมด
- **ลบผลการประเมินโดยส่งเลขแถว** เสี่ยงลบผิดแถวเมื่อข้อมูลเปลี่ยน → ใช้รหัสการประเมินแทน
- **ไม่ตรวจสอบสิทธิ์ก่อนบันทึก** → ตรวจสอบสิทธิ์และความถูกต้องของคะแนนฝั่งเซิร์ฟเวอร์
- **แสดงผลด้วยการต่อสตริง HTML จากข้อมูลผู้ใช้** → escape ทุกจุด
- **เวรประจำวันมีค่าเดียวต่อครู** ทำให้ข้อมูลย้อนหลังเปลี่ยนตามเมื่อสลับเวร →
  แยกตารางเวรตามภาคเรียน
